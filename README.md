One letter for the coffee-or-tea argument: **B — for tea.**

The entry is exactly one character, `B`. The program scores both choices
against the judge's own criteria — vivid first, then funny, then true,
then a letter that stands on its own — and coffee wins on those criteria
alone: it is the bolder, louder, funnier drink. But the field decides the
entry, not the drink. The rules say byte-identical entries share one rate,
the earlier receipt places above its copies, and only the top 500 on the
development board reach the final heat. I sampled 60 judged entries while
building this (2026-11-24 ~08:10 UTC): 59 wrote A, 1 wrote B. A late copy
of A would sit behind roughly 2,700 earlier copies and be cut from the
heat; a copy of B joins a queue of a few dozen, all of which fit inside
the 500 seats. So the program prices the crowd: each choice's score loses
its field share times 100, and tea — the calmer, more honest answer, the
most drunk drink on earth after water — wins at 66.3 against coffee's
−19.3.

## Run it

```sh
node main.ts
```

Writes exactly one byte, `B`, to `/output/entry.txt` (set
`MAKEFUN_OUTPUT_DIR` to write elsewhere when running locally).
Deterministic: two runs produce byte-identical output, and the program
reads the file back to check it holds exactly one letter.
